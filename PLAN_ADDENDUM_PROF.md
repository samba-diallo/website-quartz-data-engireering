## 1. Stratégie notebook : `.ipynb → HTML + iframe` (remplace `.ipynb → .md`)

### Ancienne approche PLAN.md (à abandonner)

> Tâche 1.3.3 du PLAN.md :
> ```bash
> for nb in $(find migration -name "*.ipynb"); do
>   jupyter nbconvert --to markdown "$nb"
> done
> ```

**Problème :** la conversion `.ipynb → .md` perd le formatage natif Jupyter (DataFrames Spark, plots matplotlib, sortie multi-lignes des cellules). Crée deux artefacts à maintenir (`.ipynb` source + `.md` généré).

### Nouvelle approche (prof)

Chaque notebook produit **deux artefacts distincts** dont un seul est committé :

```
docs/DE1 — Data Engineering I/lab1 practice/
└── assignment1_esiee.md            ← wrapper committé, contient un <iframe>

static/nb/DE1-Data-Engineering-I/lab1-practice/
└── assignment1_esiee.html          ← rendu HTML, regenere au build, NON committé

Data Engineering 1/lab1-practice/    (ou docs/.../assets/source/)
└── assignment1_esiee.ipynb         ← source committee, source de verite
```

**Avantages :**
- `.ipynb` reste source unique
- Rendu HTML preserve toute la sortie native (Spark UI, charts, tables)
- Le wrapper `.md` est trivial → édit Obsidian + navigation Quartz fonctionnent

**Implémentation :** `tools/notebook_to_quartz.sh` (cf. ce repo, déjà écrit).

**Config Quartz requise :** ajouter `Plugin.Assets()` aux emitters (déjà présent dans le snippet `quartz.config.ts` du PLAN.md - ne pas le retirer).

**Gitignore :** `static/nb/` doit être ignoré (régénéré au build) :
```
# Notebook HTML renders (regenerated by tools/notebook_to_quartz.sh)
static/nb/
```
